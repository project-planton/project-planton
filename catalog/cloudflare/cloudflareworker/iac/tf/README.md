# CloudflareWorker Terraform module

Provisions a Cloudflare Worker script and the companions that hang off it: workers.dev subdomain, custom domains, routes, and cron triggers.

## What this module creates

- `cloudflare_workers_script` — script, bindings (flattened from typed lists), assets, migrations, observability, placement, limits
- `cloudflare_workers_script_subdomain` — when `workers_dev.enabled`
- `cloudflare_workers_custom_domain` — one per hostname (`environment` is deprecated and omitted)
- `cloudflare_workers_route` — one per pattern
- `cloudflare_workers_cron_trigger` — when `schedules` is set
- `data.aws_s3_object` — only when `r2_bundle` is set (R2 is S3-compatible); reads the object's bytes whatever its Content-Type and refuses an empty bundle

`variables.tf` is generated by `planton tofu generate-variables CloudflareWorker`. Do not hand-edit it.

## Credentials

- **Cloudflare API token** — `CLOUDFLARE_API_TOKEN` (or `CLOUDFLARE_API_KEY` + `CLOUDFLARE_EMAIL`), read by the empty `cloudflare` provider block. This is all an inline-content Worker needs.
- **R2 key pair** — only for `r2_bundle`. `credentials.tf` declares `r2_access_key_id`, `r2_secret_access_key`, and `r2_endpoint`; Planton fills them from the Cloudflare connection's R2 keys as `TF_VAR_r2_*`. Running the module directly, set those variables yourself (a null key falls back to the storage provider's own `AWS_*` chain). The pair needs Object Read on the bundle bucket.

Without a bundle the `aws.r2` provider is configured with a placeholder key pair and every skip flag, so it makes no network call and no request is ever signed with it (`provider.tf` explains why the block exists at all).

The committed `.terraform.lock.hcl` fixes both providers, the Cloudflare one and the AWS one behind the `aws.r2` alias, to the catalog's locked releases; `tofu init -lockfile=readonly` installs exactly those.

## Outputs

`script_id`, `script_name`, `custom_domain_hostnames`, `route_patterns`, plus keyed maps `custom_domain_ids` (by hostname), `route_ids` and `route_zone_ids` (by list index) so import can reassemble `{account_id}/{domain_id}` and `{zone_id}/{route_id}`.

## Feature-gated fields

Traces `propagation_policy` needs the account's trace-propagation feature: without it Cloudflare rejects the whole script upload with 403 code 100342 (measured live). Leave it unset unless the account carries the feature.

## Usage

```bash
planton apply -f manifest.yaml --iac terraform
```
