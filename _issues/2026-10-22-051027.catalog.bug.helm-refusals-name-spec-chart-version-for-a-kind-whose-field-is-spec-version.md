# Helm refusals name `spec.chart_version` even for a kind whose version field is `spec.version`

**Area**: `pkg/failure/helm.go`, `pkg/failure/explain.go`, `pkg/kubernetes/helmcrds/failure.go`, `pkg/iac/tofu/generators/helmcrdstf.go` (and the generated `iac/tf/helm_crds.tf` of every chart kind)
**Type**: bug (a refusal's next step names a field the user cannot set)

## What a platform engineer sees

A `KubernetesHelmRelease` pinned to a chart version the repository does not publish is refused with `next step: set spec.chart_version to a version listed at <repo>/index.yaml`. That kind's field is `spec.version`, so the user is told to set a field that does not exist. The same text reaches every chart kind through the shared refusal family:

- `pkg/failure/helm.go`: `HelmVersionNotPublished` and `HelmOCIVersionNotPublished` hard-code `spec.chart_version` in Meaning and NextStep. `explain.go` rebuilds them from a provider's raw text, so it cannot know the kind's field.
- `pkg/kubernetes/helmcrds/failure.go:49,57`: the chart branch's locate and render refusals hard-code `spec.chart_version`. The bundle branch already uses `Source.VersionField`.
- `pkg/iac/tofu/generators/helmcrdstf.go:223`: the generated index postcondition hard-codes `spec.chart_version`, although the contract carries `version_field`.

## What good looks like

Every Helm refusal names the field the kind's user sets. The kept-definition path already knows it (`Source.VersionField` on Pulumi, `version_field` in the Terraform contract), so those texts take it from there. The explain path, which sees only provider text, needs the field from the engine run that called it.

Prove it with `KubernetesHelmRelease`'s `version-not-published` lane: the refusal names `spec.version` on both engines.
