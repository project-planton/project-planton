# Kubernetes statements spelled by emptiness need explicit switches

**Area**: `catalog/kubernetes/networking_v1_api.proto`, `catalog/kubernetes/core_v1_api.proto` (`KubernetesCoreV1ApiLabelSelector`), `catalog/kubernetes/kubernetesagentsandboxtemplate/v1alpha1/spec.proto`, `catalog/kubernetes/kubernetesagentsandboxclaim/v1alpha1/spec.proto` (comments), and the projection modules that render them
**Type**: feature (a statement the console cannot author), with two validation gaps and a comment gap beside it
**Tracked at**: https://github.com/plantonhq/planton/issues/632

## What a platform engineer sees

Kubernetes spells several statements by emptiness, and the console cannot send an empty value faithfully: its write path cannot tell an empty block or row the person meant from one they never filled in, so it drops both, and for these statements a dropped value means the opposite. The console therefore refuses such a save by name, and its wizards do not offer the statement. The statements:

- **Deny all traffic, on a SandboxTemplate's fence.** `network_policy: {}` (no ingress, no egress) denies everything both ways; no `network_policy` keeps the controller's secure default, which lets the sandboxes reach the internet.
- **Every namespace, or every pod, in a NetworkPolicy peer** (and in a pod affinity term). An empty `namespace_selector` selects every namespace, while none selects only the policy's own; an empty `pod_selector` selects every pod.
- **Allow everything in one direction.** A NetworkPolicy rule with no peers and no ports admits all traffic in its direction; no rule admits none.

Today a template that needs any of these is applied as YAML; editing it in the console afterwards is refused with a sentence that says so.

## What good looks like

Each statement gets a field of its own, so the manifest says it and the wire spells it, the shape the catalog already uses for a selector's `match_all` in `KubernetesNetworkPolicy`:

- `KubernetesAgentSandboxTemplateNetworkPolicy.deny_all` (`optional bool`, `manifest_only`): true renders `networkPolicy: {}`; refused beside any rule.
- `KubernetesCoreV1ApiLabelSelector.match_all` (`optional bool`, `manifest_only`): true renders `{}`; refused beside `match_labels` or `match_expressions`. Every faithful kind that embeds the selector gains it at once.
- `KubernetesNetworkingV1ApiNetworkPolicyIngressRule.allow_all` and the egress twin (`optional bool`, `manifest_only`): true renders the empty rule; refused beside peers or ports.

The mirror test must accept a `manifest_only` field the served schema does not carry, and the projection path (both engines) must render the upstream spelling and drop the marker, as the marker's own contract says. Once a release carries them, the console's refusals are deleted and its fence and peer editors offer the statements.

## Two validation gaps and a comment gap, found beside it

- **An empty NetworkPolicy peer.** The NetworkPolicy API refuses a peer that names no pod selector, namespace selector or IP block; `KubernetesNetworkingV1ApiNetworkPolicyPeer` accepts `{}`, so the template applies and its policy then fails to reconcile.
- **`end_port` has no upper bound.** The NetworkPolicy API requires `endPort` to be at most 65535; `network_policy_port.end_port_range` checks only that it is at least `port`.
- **`KubernetesAgentSandboxTemplateSpec.pod_template`'s comment** says a warm pool rolls "its members" to a changed template. It rolls its unclaimed members; a claimed sandbox keeps the pod it was built with. The catalog page now says so; the comment every generated surface reads does not.
- **`KubernetesAgentSandboxClaimSpec`'s comments** do not say that a claim's sandbox keeps the shape it was built with: at agent-sandbox v1.0.7 the controller patches only its pod labels and annotations, so a changed pool, variable or volume reaches the claim's next sandbox. The claim's README, guide and catalog page say so.
