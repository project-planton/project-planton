# KubernetesOtelOperator: the admission proof passes on an operator panic

**Area**: `catalog/kubernetes/kubernetesoteloperator` (its e2e verifier `catalog/kubernetes/aa_e2e/verify/oteloperator.go`)
**Type**: bug (a lane proves less than it claims)

## What a platform engineer sees

On Kubernetes 1.37 (kind v0.33's default node image), the `minimal` lane's admission check rejects the verifier's invalid OpenTelemetryCollector through the operator's mutating webhook `mopentelemetrycollectorbeta.kb.io` with `panic: assignment to entry in nil map [recovered]`, not with a validation message. The lane passes on both engines: the check accepts any rejection. But a webhook that panics on a malformed object may also panic on a valid one a user writes, and the lane would not tell.

## What good looks like

The admission proof asserts the rejection names the invalid field, so a panic fails the lane. Then either the chart pin moves to an operator release whose webhook validates on Kubernetes 1.37, or the kind documents the version range it is proven on.
