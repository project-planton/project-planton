# The Agent Substrate resources are proven live, an actor sleeps into storage and wakes with its files, and keyless storage is proven on GKE

## What the lanes proved, on both engines

- **KubernetesAgentSubstrateSandboxConfig:**
  - Every field reads back.
  - The control plane's API resolves the config for a template of its class and refuses it for a microvm one.
- **KubernetesAgentSubstrateCsiDriverConfig:** every field reads back (a CSIDriverConfig has no status).
- **KubernetesAgentSubstrateWorkerPool:** the class resolves to its SandboxConfig, the workers become ready, and the API lists them active.
- **The actor lane:**
  1. An actor is created from upstream's counter template on gVisor workers.
  2. It answers through the router (`ate-target-actor`), memory 1 and file 1.
  3. It is suspended into the S3 store, with its snapshot objects found in the bucket.
  4. It is resumed and answers again with its files: memory 1, file 2.
- **On GKE** (a throwaway 1.37 cluster, Workload Identity, Dataplane V2):
  - The control plane's storage identities write, read back and delete in the GCS snapshot bucket with no key.
  - The agent-sandbox router reaches its sandboxes behind its default NetworkPolicy.
  - The batch's teardown audit is clean.

## What changed

- **A prerequisite is verified with the prerequisites before it.** The runner verified each prerequisite with only its own manifest in context, so a fixture proven through what it composes with (a SandboxConfig through the control plane's API) could not prove itself as a fixture. It now gets the same verify context as a scenario phase.
- **The docs:**
  - `e2e/README.md` says CI reads the committed matrix, regenerated by `make e2e-matrix`, rather than discovering it live, and how prerequisites are verified.
  - The harness README notes the kind-version refusal.

All nine agent runtime kinds' profiles are `green` with both engines validated, and the CI matrix is regenerated.
